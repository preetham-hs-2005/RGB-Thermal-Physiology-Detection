# Dataset research and acquisition plan

Reviewed 2026-11-13 (Asia/Calcutta). This is an evidence and action record for the PDF-led, multi-domain project. Current status and requirement decisions remain in [TR.md](TR.md) and [NTR.md].

## Decision

**Use datasets as task-specific evidence, not as a single pooled training set.** The project now covers multiple body regions and nonclinical RGB–thermal tasks. No verified source covers every target capability across all domains. Most importantly, no source verified so far provides paired, synchronized radiometric human images, a defined clinical outcome, and independent abnormality-region masks across multiple body regions. A dataset can support only the tasks represented by its files and annotations. Artificially pairing unrelated RGB and thermal images is not valid multimodal evidence.

Each clinical target must be specified before recruitment. Facial elevated-temperature screening, knee inflammation, postoperative wound complications, and adolescent anterior knee pain have distinct sensors, populations, and reference standards; do not combine their positive labels into one universal “abnormality” class.

## Recommended sequence

1. **Build the general data contract and manifest.** Define one paired record with optional modalities, timestamps, source provenance, transform, calibrated temperatures and validity masks (TR-001, TR-002, TR-015). Synthetic samples verify code paths but remain labeled synthetic.
2. **Use the three acquired domains for separate tasks.** Caltech for RGB/thermal environmental semantic segmentation; StereoThermoLegs for body-part segmentation; FDA tables for temperature/reference statistics. Keep each label map, split, metric and model head separate.
3. **Validate registration on files with enough geometry.** Start with dataset-provided rectification or calibration; measure held-out landmark/mask error. Then compare calibrated projection, homography baseline, and feature/mutual-information fallback. Avoid clinical interpretation where the thermal values are not verified radiometric °C.
4. **Clinical wound localization is access-gated.** Use the pretrained dual-stream transformer/query-mask design in `PROCESS_MODEL_DESIGN.md`; compare RGB-only, thermal-only, and fusion on the same patient-disjoint splits. The Caltech U-Net remains a nonclinical pipeline smoke test and is not the medical architecture.
5. **Keep gated sources optional.** Post-TKA, IRKTD, OSTHERSIT, anterior-knee-pain and JIA remain separate future candidates with access, clinical-task and label requirements. Do not let a nonclinical or CSV-only dataset stand in for clinical image validation.
6. **Generalization gate.** Hold out subjects, scenes, trajectories, or geography according to intended use. Only make cross-domain claims where labels and target meanings agree; localize clinical abnormality only against independently marked clinical regions.

### Earlier nonclinical candidate shortlist (not the current implementation order)

1. **PST900 first**, after confirming the dataset-use terms. It offers the most useful bundle for the next implementation step: paired modalities, depth, raw thermal encoding, calibration/registration tooling, and pixel masks in a manageable archive.
2. **LLVIP next** for low-light pedestrian detection and a raw-pair registration case. Its noncommercial terms are explicit, but require agreement and form-based access.
3. **FLIR ADAS** when a broader detection task and 14-bit pre-AGC files are desired; review the download terms and conversion metadata first.
4. Use the **KAIST preview** only if we need a conventional, larger pedestrian benchmark. Defer the 36 GB full archive until storage, sequence-level evaluation, and license handling are planned.
5. Add one **tracking** dataset (LasHeR) or one **larger day/night segmentation** dataset (Freiburg Thermal) only if that task becomes part of the implementation milestone. They are not required before the paired-frame contract.

No open candidate in this shortlist provides the complete target of paired RGB, calibrated radiometric human temperatures, independent clinical outcome labels, and independently annotated abnormality regions. Existing restricted clinical leads remain in the fit matrix above and require separate permissions.

The project has since acquired TRICVI-C and LUTSeg for two distinct clinical data tasks. The current immediate implementation order is: (1) build a LUTSeg RGB-only dataset adapter and mask preview, (2) parse TRICVI-C Celsius grids and co-indexed frames, then (3) implement and measure RGB/thermal alignment on held-out reference points. Preserve each task separately. The older post-TKA access request is not a prerequisite for these steps.

## Minimum dataset acceptance checks

For each candidate, record a versioned manifest and **one inspected example** before building on it:

- **Pairing:** RGB and thermal file IDs, subject/session IDs, timestamps or documented synchronized capture; no cross-subject matching.
- **Thermal semantics:** file encoding, per-pixel value-to-°C conversion, invalid/saturated pixel convention, emissivity/reflected-temperature settings, calibration information and sensor model. A colored JPEG or intensity-only PNG fails the absolute-temperature gate.
- **Geometry:** image dimensions, view/side, intrinsics/extrinsics or calibration correspondences, transformation direction, and a held-out alignment check.
- **Labels:** precise clinical target and reference standard, label date relative to imaging, annotator role, separate anatomical ROI masks and abnormality masks, and missing-label policy.
- **Governance:** license/DUA, consent or deidentification basis, permitted derivative/publication use, storage and access rules. Keep restricted source images outside Git.
- **Evaluation:** count **unique people**, not just frames; reserve subject-disjoint partitions, preserve an external cohort when possible, and report site/device/ambient differences.

If a candidate fails a gate, retain it only for the narrower task explicitly supported by its contents. Keep a dataset registry in future implementation with these fields and a recorded license decision.

### TRICVI-C v2 — paired RGB, thermal and numeric temperatures

- **Official record:** [Mendeley Data, DOI 10.17632/rf5m97cmm3.2](https://data.mendeley.com/datasets/rf5m97cmm3/2); public dataset API was used for download. The owner record states CC BY 4.0.
- **Local status:** `datasets/tricvi_c/`; 1,284/1,284 files downloaded, 318,816,132 bytes. Every file's SHA-256 and byte count matched the public API metadata. The archive has 427 numeric CSVs, 854 JPEGs, two protocol/readme PDFs, one clinical workbook and one metadata file.
- **Inspected example:** FLIR1753 has a 640x480 visible leg RGB JPEG, a 320x240 FLIR thermal display JPEG with displayed temperatures, and a numeric 320x240 CSV temperature matrix whose cells are in °C. The CSV specifies emissivity 0.95, reflected temperature 20°C, distance 1 m and other camera/environment parameters. This example's measured grid spans 21.73–33.43°C (mean 24.00°C). The CSV and two images share the FLIR frame ID, establishing an acquisition-level correspondence. The dataset protocol describes standardized lower-limb views and CEAP-based clinical characterization.
- **Labels and caveat:** the included clinical workbook lists 71 volunteers and aggregate CEAP counts C0–C6 = 21/4/21/16/4/2/3. The downloaded file manifest exposes opaque Mendeley folder UUIDs and FLIR frame IDs, but we have not recovered a verified mapping from volunteer codes in the workbook to image groups. Do not attach class labels, create patient splits, or train a CEAP classifier until this key is recovered and checked.
- **Supported now:** implement RGB/thermal/Celsius loading, sample temperature statistics, and a visual alignment/coverage review. It does not provide wound-tissue masks or a pixel-level abnormality target. The CSV's °C values and existence of same-ID images do not establish precise geometric co-registration. The demonstrator resizes the thermal grid by 2x for display; no independent landmarks or held-out alignment error have been measured.

### Baseline demonstrator and model implications

`scripts/build_review_demo.py` builds `outputs/baseline_review_demo/index.html`, an offline review page containing the TRICVI-C RGB/thermal/temperature sample and the LUTSeg wound/mask sample. It labels LUTSeg annotations as ground truth and explicitly marks the thermal overlay as scale-only and unvalidated. The samples are from different source cohorts; they are not paired with each other and do not constitute one multimodal wound experiment.

The LUTSeg RGB-only DINOv2-small + dense Transformer decoder baseline is now trained and runs in `scripts/run_lutseg_baseline.py`. Its 8-epoch CPU run used the official 111/30 patient-disjoint split and achieved best validation mIoU 0.331 including background (foreground-only macro mIoU 0.216); full report and weights are in ignored `outputs/lutseg_transformer_baseline/`. The small validation set was used for checkpoint selection, there is no independent test split, and the rare Other class scored zero IoU. The earlier dual-stream DINOv2/query-mask code remains an untrained, access-gated post-TKA scaffold. TRICVI-C exercises RGB/thermal/Celsius ingestion and registration review as a separate task. A true RGB+thermal wound model still needs a single approved cohort with both modalities and independent wound masks.
